# Codex instructions — BLINKA Layer 1 v3.0

The normative documents are `docs/L1-v3.0-ARCHITECTURE.md`, `contracts/l1.contracts.ts`, `docs/ADR-003-L1-v3.md`, and `tests/DEMO-DAY-8-SCENARIOS.md`. Treat `L1_CONTRACT_VERSION = 3.0.0` as a versioned API; reject or explicitly migrate v2 envelopes instead of silently accepting them.

**Ownership:** L1 owns immutable document sources, parsing, structured extraction, source-backed evidence, deterministic normalization and verification. L2 exclusively owns payment-policy and ledger-based authorization. L3 owns team governance, cross-source `PayableCase` correlation, HITL and evidence admission. Do not implement L2/L3 inside L1. Do not process real payments or use customer data.

**Implement first:** TypeScript strict Zod runtime schemas, decimal.js FX normalizer, source digest binding, verifier, fixture generators and Vitest unit tests. Conversions: USD identity, COP 4,000/USD, MXN 20/USD in the synthetic demo. Require currency pair match, exact decimal arithmetic, positive rates, fixed HALF_EVEN rounding and recorded snapshot IDs. The above demo quotes are fictional, not live market data.

**Later:** LiteParse digital PDF, LlamaParse visual parsing, optional DocJev splitting, LlamaExtract extraction through adapters; integration and e2e tests. Never trust extractor confidence as authorization or a citation to OCR alone as proof of optical correctness. Persist failures, use access-controlled artifact storage, and redact account identifiers in UI logs.

**Demo:** `fixtures/demo-day-8-scenarios.json` defines synthetic ground truth and expected L2 decisions, NOT finished PDF fixtures and NOT passing tests. Produce genuine synthetic input files and executable assertions; verify scenarios against explicit independent starting states. `sourceIds` in case 4 are correlated by L3, not merged by L1. Case 5 references a seeded prior ledger invoice; case 7 starts from a pre-seeded USD 1,400 budget.

Do not claim production safety or passing OCR tests until provider integrations and adversarial evaluations actually pass. Document provider versions, tests, latency, costs, and remaining risks.
